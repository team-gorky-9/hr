## Версии и строки

Версии профиля, схемы пакета, params и ревизия случаев независимы. Загруженная Денисом v2 сохранена на `39260997bd11db41054bfb04544e382dcdf40181`; последующие v3 уточняли критерии, Python v4 добавил same_as ПДн. Новые v4/v5 реализуют содержательные решения. Ключи и source_refs сохранены; загрузчик не должен переписывать уже загруженный номер версии. Учебный v2 остаётся в отдельном контуре.

У каждого условия и индикатора есть is_mandatory, verification, check_stage, acceptance и происхождение. origin=source требует документа, адреса и цитаты; origin=team — rationale. У групп и контекстных строк нет самостоятельной проверки. interpretation_status=proposed сохраняет отсутствие предметного утверждения работодателем; принятие интерпретации командой отражено в team_review, а групп Python — в grouping_status=accepted_by_team.

Все индикаторы консультанта обязательные по принятой интерпретации матрицы. Ранги и исходные диапазоны сохранены: ДК 100–100, остальные 90–100. Это данные эталона, не расчёт пригодности кандидата. У Python ранги/проценты null. hr.DK.19 (право знакомиться с документами) и hr.RK.03 (повтор hr.DK.06) исключены из оценки, исходные строки сохранены.

same_as=py.same-as.personal-data-law объединяет только py.di.P112 и py.di.P209, обе на interview в SECURITY. Применение ПДн P134 отдельно. PostgreSQL и желательный ClickHouse не объединяются; знание темы и практическое применение не тождественны. У источников сохраняются role и revision; редакция ДИ Python — 1.2 от 01.02.2024.

## Правила и границы

Внутри альтернативы AND, между альтернативами OR; requires_requirement связывает направление с подтверждённым уровнем соответствующей записи образования. Отсутствие сведений не означает not_met. Неизвестное правило останавливает всю оценку до модели и сохранения, это не unknown кандидата. Реальный опыт Python не имеет численного минимума и дополнительного ограничения «коммерческий»; учебные 24 месяца к нему не относятся.

Условия screening задают допуск по резюме. Законы, английский, ПДн и поведенческие качества — интервью. В v1.5 подтверждённое образование по резюме сохраняет met при verification=documents: basis=resume, is_preliminary=true, подпись «по резюме, нужен документ». Общее правило предварительности: result != unknown и basis != verification, без иерархии способов.

Для technical необходим учебный кандидат и явный выбор неархивного draft либо утверждённый учебный профиль по умолчанию; operational — реальный кандидат и утверждённый рабочий профиль. Это согласованный целевой контракт после интеграции #10, не подтверждение адаптации текущего оценщика. Разрешение approve синтетики не утверждает конкретный учебный профиль.

## Карточки, цитаты и идентификаторы

В прежних 41 случаях card_role=expected_available_fields обозначает ручное ожидание доступных полей CandidateCard, а не результат извлечения моделью. card_evidence связывает фактические поля через JSON pointer с цитатами. Валидатор проверяет наличие полей и ссылок, не семантическую полноту. Отсутствующие названия работодателя, даты, курс или специальность не выдуманы. missing описывает пробелы, card_limitations — сведения, не представимые старой схемой этой ветки. После интеграции v1.4/v1.5 эти сведения можно переносить отдельно с проверкой извлечения.

В hr-field-no отсутствие переподготовки подтверждается собственной цитатой, не пустым courses. В py-education-met field=null: название специальности не задано; техническое образование подтверждается текстом. Исторический ID py-relevant-met сохранён с результатом unknown из-за неясного характера проекта; py-relevant-work-met содержит явный рабочий контекст. Суффикс ID не определяет исход.

case.evidence — общий список; formal_evidence_indexes и indicator_evidence_indexes разделяют основания. alternative_evidence_indexes связывает исходы альтернатив с цитатами. Цитата об API-тестах не подтверждает длительность стажа. Позиции — [start,end) исходного текста.

UUID: uuid5 с namespace d0137233-a161-59f2-876e-34ec1c1142a6 и text_key; первые три ключа — py-9001/text/base, py-9001/text/met-3y, py-9001/text/not-met-1y. Изменённый текст требует нового версионного ключа; text_sha256 защищает соответствие. previous_candidate_text_id сохраняет исторические связи. Это правило синтетики, не изменение UUID БД.

## Совместимость и передача

Актуальные v4/v5/учебный v2 проверены офлайн реальным build_profile и схемами из снимка Дениса `3f0d88f6222361c26eefceec86ff84ab720f4bb2` (БД v1.5, PR #10). Приняты 113 этапов, 41 карточка и 53 цитаты. Это не транзакция PostgreSQL и не прогон модели. Последний проверенный origin/main — bb2c192, рабочая база — 206260e; снимок v1.5 ещё не интегрирован в этот checkout.

В v1.5 сохраняются check_stage и acceptance строк, но same_as двух индикаторов остаётся только в файле. Прочие поля ревью также не обязаны переноситься; точное отображение — в [requirements.md](../../docs/contracts/requirements.md). В текущем старом загрузчике check_stage ещё теряется. Повторный загрузчик не создаётся.

Илья подтвердил адресный прогон 41 случая после адаптации к v1.5: сравнивать только размеченный rule_key, зависимости и цитаты. Полная дополнительная разметка не нужна. Для новых 16 примеров требуется отдельное подключение; интервью-примеры не превращаются в screening. В проверенной ветке Ильи acceptance не передаётся модели — это отдельное необходимое изменение потребителя. Денису остаётся хранение same_as, Илье — агрегация.

Рабочий утверждающий и актуальность правовых ссылок не подтверждены; профили остаются draft, operational_use_allowed=false. Источники правовых названий сохранены дословно, автоматическая замена законов не выполняется.

## Воспроизведение проверок

Из корня hr с зависимостями продукта:

```powershell
uv run python -m scripts.verify_requirement_profiles --card-schemas --content-cases fixtures/requirement_profiles/synthetic/content-cases.json
uv run python -m scripts.verify_requirement_profiles --archive "C:/path/to/Кадры.zip"
uv run python -m pytest tests/test_requirement_profiles.py tests/test_requirement_content_cases.py -q
```

Проверяются структура, ключи, хеши/цитаты манифеста, карточки, границы evidence, UUID, группы same_as и применимость этапов. Флаг --archive дополнительно сверяет исходные байты DOCX/TXT и извлечённые абзацы. CLI не вычисляет семантические ожидаемые исходы.

Из штаба: `hr/.venv/Scripts/python.exe -X utf8 tools/check_requirement_profile_handoff.py` проверяет сохранность ключей/источников относительно v2 и преобразование старым загрузчиком; `hr/.venv/Scripts/python.exe -X utf8 tools/check_requirement_profile_v15.py` проверяет отображение на v1.5. Оба работают с полученными Git-объектами без БД. Отчёт текущего шага — в штабном verification.md.
