# Реестр публикаций · пакет Давида

**Версия:** `2026-11-20.1-draft`. **Назначение:** предметная сверка requirements-03 и передача Родиону. Формат предложен для согласования; приложение его пока не читает. Решений кадрового владельца о положительном соответствии или отсутствии подходящей должности нет.

- [Реестр JSON](register.v1-draft.json): семь буквальных названий, контекст набора и канала, частоты, основания, вопросы и ответственные.
- [Основания](evidence.json): восемь адресованных фрагментов [оригинала ДИ](sources/hr-consultant.docx), проверяемые по SHA-256 и OOXML. Подписи и реквизиты утверждения из шаблона не считаются состоявшимся утверждением.
- [Покрытие](coverage.json): новый разбор реального архива текущим продуктовым парсером, без БД и модели.
- [Примеры](synthetic-cases.json): синтетические сценарии для согласования, не результаты интеграционного запуска.
- [Описание предлагаемого формата](../../docs/contracts/posting-position-register-proposal.md).

## Что показать кадровому владельцу

Сначала открыть ДИ: P60 — точная должность, P67 — подчинение, P102 — подбор и оценка кандидатов. Затем для каждой публикации запросить её текст, подразделение и применимую ДИ. Общие упоминания муниципальной службы, документов или обращений не доказывают совпадение должностей.

| ID / публикация | DOCX | Основание и нерешённый вопрос |
|---|---:|---|
| `hr-work` · Консультант отдела кадровой работы | 122 | P60, P67, P102. Это сектор подбора кадров или другая кадровая функция? Нужна связь подразделения и обязанностей с этой ДИ. |
| `development` · Консультант отдела профессионального развития | 58 | P63, P65, P102. Развитие кадрового состава названо широко; является ли основной функцией именно подбор, а не обучение? |
| `appeals` · Консультант отдела по работе с обращениями граждан и предпринимателей | 28 | P60, P102, P108. Обращения в ДИ ограничены деятельностью сектора. Нужна ДИ отдельного отдела обращений. |
| `financial-control` · Начальник отдела внутреннего финансового контроля, аудита и закупок | 20 | P60, P67, P102. Уже mismatch к hr-consultant. HR должен отдельно подтвердить целевую должность либо отсутствие подходящей среди шести. |
| `municipal-service` · Консультант отдела муниципальной службы | 9 | P62, P63, P67, P102. Область службы не определяет подразделение: нужна связь с функцией подбора. |
| `documentation` · Консультант отдела документационного обеспечения департамента обеспечения деятельности главы города | 4 | P60, P67, P96, P102. Подготовка документов сектора не доказывает соответствие другому отделу и департаменту. |
| `estimator` · Сметчик | 1 | P60, P102. Уже mismatch к hr-consultant. Отсутствие подходящей должности во всём каталоге ещё не утверждено HR. |

По каждой строке ответ получает **Давид**; решение принимает **уполномоченный владелец кадрового процесса**, личность пока не установлена. Автор, дата и основание решения в JSON равны `null`, а не имени исполнителя или дате подготовки. Все семь `decision_state=needs_review`; две записи дополнительно сохраняют существующий `current_policy.status=mismatch`.

**45 без публикации** — отдельная совокупность, не восьмая публикация. У трёх из них есть история: её названия не подставляются вместо подвала. `242 + 45 = 287`; это файлы/записи, не число уникальных людей.

## Что зафиксировать после ответа HR

Для каждой строки: ID, неизменённое исходное название и контекст, `confirmed` с одним кодом из справочника либо `no_matching_position` либо сохранение `needs_review`, ссылка на текст публикации/ДИ/решение, кто уполномоченно решил и дата. При неоднозначности или противоречии остаётся `needs_review`. Опубликованную версию не перезаписывать: новое решение — новая версия пакета. Сначала Родион согласует формат и чтение с потребителями.

Для реальной оценки отдельно нужен действующий рабочий approved-профиль. Подтверждение маппинга не утверждает профиль. В реестре нет вымышленных position_id и UUID профилей; их получает потребитель в своей БД. Контекст IT-папок и их ДИ/«Вакансия.txt» подготавливается отдельно: этот пакет не переносит правило папки на смешанные DOCX.

## Проверка и ограничения

Из корня продукта, Python 3.13, без установки зависимостей и БД:

```console
python scripts/verify_posting_register.py
```

Повтор реального разбора требует зависимостей продукта и исходного архива:

```console
python -m scripts.report_profile_applicability "<Кадры.zip>" --output "<локальный-отчёт.json>"
```

Локальный архив SHA-256 `801efb82667a63d5d2370e6d39b00c74bea5069a3643472d41f476348a559baf`. Прогон на `fec6bd2`: 287 записей; политика 1.0 — 0 confirmed, 21 mismatch, 266 unresolved; внешняя история — 24 записи в **четырёх** файлах (2, 2, 8, 12). Ранняя постановка сообщает шесть файлов; старый продуктовый отчёт на архиве `14a9a843…` также сообщает четыре. Это открытое расхождение для Дениса, а не исправленный факт импорта. Факт наличия внешних записей нельзя использовать для восстановления неизвестного подвала.

Проверены содержание пакета, цитаты и агрегаты; подключение реестра к resolver/API, выбор approved-профиля и воспроизведение T-13 через БД здесь не реализованы и не проверены.
