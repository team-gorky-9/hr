# Практика студентов через API

Компонент StudentsWorkspace использует существующие Card/Btn/Badge и общий дизайн. Путь включает место → заявку → назначение → задание → сдачу/доработку → проверку → отдельные итоги принимающей стороны и вуза → интерес и prepared-пакет. Данные сохраняются сервисом Students в БД.

## Подключение и запуск

Default export — src/components/students/StudentsWorkspace.tsx. VITE_STUDENTS_API_BASE по умолчанию /api/v1/students. Прокси этого префикса должен идти на Students отдельно от legacy /api/v1. Проверенный STUDENTS_API_TARGET — http://127.0.0.1:18505.

Из services/students выполнить uv sync --python 3.13 --dev, создать data, установить STUDENTS_DATABASE_URL=sqlite:///data/frontend-practice.db, выполнить uv run alembic upgrade head. Запуск — uv run uvicorn students.main:app --host 127.0.0.1 --port 18505.

API использует штатные fixture:hr, fixture:candidate, fixture:department. В UI есть явная метка учебных участников. Это серверная fixture-авторизация, данные интерфейса поступают из настоящих HTTP-ответов.

## Точный ручной сценарий

1. Открыть «Практика студентов». Роль **Организатор практики** → **Создать место практики**. Название **Учебная практика — классификация обращений**, задача **Классифицировать обращения и объяснить выбранную категорию**, даты **01.12.2026–31.12.2026**. Создать черновик и нажать **Опубликовать место**. Ожидается статус «Приём заявок» и одно свободное место.
2. Роль **Студент** → **Подать заявку**. Вуз **Учебный вуз**, программа **Государственное и муниципальное управление**, комментарий **Учебная заявка 21 ноября**. **Подать заявку на практику**. Ожидается «Заявка подана».
3. Роль **Организатор практики**. У заявки основание **Даты и учебный наставник подтверждены HR** → **Назначить место**. Появляется назначенное участие.
4. Роль **Наставник**. Открыть участие. Название задания **Классификация обращений**, описание **Распределите три обращения по темам и объясните решение**, критерий **Категория каждого обращения обоснована** → **Опубликовать задание**.
5. Роль **Студент**. Открыть участие. «Моя работа» — **Распределил обращения без пояснений** → **Отправить работу наставнику**. Ожидается «Ожидается проверка наставника».
6. Роль **Наставник**. Открыть участие. Результат проверки — **Нужна доработка**, основание — **Добавьте объяснение выбора категории** → **Сохранить проверку**.
7. Роль **Студент**. Открыть участие. Видно замечание. Новая работа — **Категории выбраны по предмету обращения, объяснение добавлено** → отправить. Появляется вторая попытка, первая сохраняется.
8. Роль **Наставник**. Проверить вторую попытку, результат **Подтверждено**, основание **Категории объяснены и соответствуют предмету обращений** → сохранить. В правой колонке итог **Завершена полностью**, основание **Исправленная работа подтверждена** → **Зафиксировать итог практики**. Вузовский результат пока неизвестен.
9. Роль **Организатор практики**. Открыть участие. Вузовский результат **Зачёт получен**, источник **Учебное письмо DEMO-6A**, автор **Учебный координатор вуза**, дата **31.12.2026** → **Записать результат вуза**. Учебная будущая дата не обозначает произошедший рабочий факт.
10. Роль **Студент**. Пожелание **Хочу обсудить работу после выпуска** → **Выразить интерес к работе**.
11. Роль **Организатор практики**. Выбрать подтверждённый критерий в блоке пакета. Цель **Рассмотреть после выпуска**, основание контакта **Студент выразил интерес в кабинете** → **Подготовить пакет**. Видно подготовку и ожидание передачи в архив. Диплом остаётся неподтверждённым.
12. Обновить страницу, выбрать роль и открыть участие. История, работы, отзывы и два отдельных итога читаются из БД.

Отрицательный случай — завершение полностью до подтверждения критерия. Сервер отказывает с понятной причиной, результат не записывается.

## Границы

Форма места использует одно учебное место и штатного наставника department. Групповое распределение и справочник наставников требуют дальнейшего интерфейса. Подготовка пакета подтверждается в текущей сессии; API не даёт списка пакетов по участию. Реальной передачи в архив нет. Ссылка на работу хранится как внешний изменяемый ресурс, текст работы сохраняется в сервисе.
