# Архив резюме с настоящим API

В кабинете HR открыть «Архив резюме». Выбрать целевую вакансию, описать нужный опыт, выполнить поиск, открыть найденную запись. Карточка показывает источник с проверенной цитатой, прежние рассмотрения и действующую подборку под выбранную должность. Если подборки нет, HR заполняет профессиональное основание и основание контакта. После внешнего обращения и согласия человека HR фиксирует подтверждение и начинает рассмотрение.

Список, карточки, цвета, шрифты и поля используют существующий дизайн. «Кадровый резерв» остаётся отдельным разделом. API поиска отдаёт candidate_code и профессиональные сведения, имя/контакты не выдумываются. Оценка соответствия вакансии отдельно от поиска.

## Запуск

В frontend выполнить npm ci и npm run dev. Dev-прокси /api/v1 ведёт на ARCHIVE_API_TARGET (по умолчанию http://127.0.0.1:8000).
VITE_ARCHIVE_CONTOUR=training по умолчанию, серверные синтетические записи помечены в UI. Прокси добавляет учебный X-User-Login из ARCHIVE_DEMO_LOGIN (по умолчанию hr_demo). Для working установить VITE_ARCHIVE_CONTOUR=working, а на доверенном шлюзе проверять кадровую сессию и добавлять заголовки legacy и серверный поисковый токен. Рабочие секреты не должны быть VITE-переменными.

VITE_ARCHIVE_API_BASE задаёт путь API для сборки, по умолчанию /api/v1. В production этот путь обслуживает доверенный reverse proxy. Vite dev proxy не является производственной авторизацией.

Для самостоятельной проверки нужен отдельный PostgreSQL с pgvector, миграции и штатный python -m app.search load-demo. Лексический поиск работает без загрузки модели.

## Данные и границы

Результаты приходят по POST /search/candidates. Вакансии читаются из GET /vacancies, цитата — GET /candidate-texts/{id}, история — GET /applications/{id}/history, подборка — GET /positions/{id}/reserve. Сохранение основания — POST /reserve. Новое рассмотрение — [добавленный endpoint](../docs/contracts/archive-reconsideration.md).

Сетевая ошибка показывает ошибку и повтор. Пустой результат появляется только после успешного запроса с нулём строк. Новые записи перечитываются после обновления из PostgreSQL, заглушек у этого раздела нет. Остальные разделы исходного frontend могут содержать свои прежние демоданные.

Приглашение пока передаётся через внешний канал. Интерфейс фиксирует согласие со слов HR и не утверждает, что письмо отправлено системой. Свежесть и содержимое резюме видны по версии доступного текста, отдельная дата исходного документа API поиска сейчас не отдаётся.


## Точная ручная проверка

Сценарий использует штатные 18 записей app.search load-demo и настоящий API учебной БД. Вверху должна быть метка «API · учебные записи». Проверенный локальный адрес — http://127.0.0.1:18417.

| Шаг | Куда нажать и что ввести | Ожидаемый результат |
|---|---|---|
| 1 | В верхней панели «Кабинет HR-менеджера», затем «Архив резюме» | Поля целевой вакансии и нужного опыта |
| 2 | «Целевая вакансия» — **Python-разработчик** | Вакансия без слова Junior |
| 3 | «Нужный опыт» — **Python FastAPI**. Флажок «Только действующие подборки» выключен. Нажать «Найти кандидатов» | Одна запись **search-9006** с фрагментом «Разворачивал Python-сервисы на FastAPI. Писал API-тесты и запускал их в CI.» |
| 4 | Нажать **search-9006** | Карточка, источник с выделенной цитатой и подборка на выбранную должность |
| 5 | Если показана форма подборки, в «Почему рассматриваем» оставить фрагмент. В «Основание контакта» ввести **Учебный пример. Согласие на повторный контакт получено 21.11.2026 по телефону.** Нажать «Сохранить в подборку» | «Подборка сохранена», основание, дата и автор. Если запись уже есть, проверить её и перейти к шагу 6 |
| 6 | «Когда и как получено согласие» — **21.11.2026, телефонный разговор. Кандидат согласился на рассмотрение вакансии Python-разработчик. Учебный пример.** Нажать «Начать рассмотрение» | При первом выполнении «Новое рассмотрение создано», этап «Новый отклик», подтверждение и автор HR |
| 7 | Обновить страницу, повторить шаги 1–4 | Подборка и рассмотрение прочитаны из базы. Нажать название прежнего рассмотрения и увидеть его историю |
| 8 | Повторить ввод согласия и нажать «Начать рассмотрение» | Сообщение о существующем рассмотрении. Дубликата нет |
| 9 | «К результатам поиска», запрос **коронограф телескопа**, «Найти кандидатов» | Ноль записей и предложение изменить условия |

search-9006 уже имеет учебную подборку по направлению, поэтому в поиске возможна отметка «Есть действующая». На карточке показана подборка именно по должности выбранной вакансии.

Для проверки прежней истории выполнить поиск **BPMN**, открыть **search-9001**, нажать запись в «Прежних рассмотрениях». Появятся этап, даты и сохранённые события. Выбор целевой вакансии сам по себе не является оценкой квалификации.

При остановленном API запрос показывает ошибку с повтором. Старые результаты не заменяют ошибку успешной выдачей.
