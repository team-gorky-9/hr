# Развитие сотрудника

Раздел использует настоящий Workforce API. Вход — серверная сессия через POST /api/v1/sessions. На экране доступны свои или адресно направленные цели, предложения планов, работы, заключения и итог. Общий переключатель кабинетов не заменяет вход в Workforce.

## Запуск и подключение

Из services/workforce выполнить uv sync --locked. Задать DATABASE_URL=sqlite:///development-ui.db и AUTH_MODE=workforce, затем python -m workforce prepare и uvicorn workforce.api:create_app --factory --host 127.0.0.1 --port 18501. Все команды выполняются интерпретатором .venv/Scripts/python.exe либо uv run.

Компонент — default export src/components/development/DevelopmentPage.tsx. API-клиент использует VITE_DEVELOPMENT_API_BASE, по умолчанию /workforce-api. Прокси этого пути должен вести на http://127.0.0.1:18501/api/v1. В production использовать доверенный same-origin gateway и рабочую БД. Токен остаётся в памяти компонента; после обновления страницы нужно снова войти, сохранённые данные читаются из сервиса.

Сервис подготовит учебные учётки employee/123 и department/123. Код руководителя и проверяющего в этом наборе — 00000000-0000-4000-8000-000000000103. Это существующий серверный seed. Экран показывает код вошедшего пользователя для назначения. Каталог других акторов доступен через API только кадровым ролям, поэтому сотрудник указывает известный код явно.

## Точный сценарий проверки

1. Открыть «Развитие». Логин **employee**, пароль **123**, нажать **Войти**.
2. В форме **Личная цель** ввести название **Аналитическая сводка**. В поле **Рабочая задача и исходные основания** ввести **Источник — ДИ экономиста, версия 2. Хочу самостоятельно готовить сводку с проверяемыми источниками.** Нажать **Сохранить личную цель**.
3. У цели статус **Личная цель**. В **Код учётной записи руководителя** ввести **00000000-0000-4000-8000-000000000103**, нажать **Передать цель руководителю**. Статус — **Передана руководителю**.
4. Нажать **Выйти**. Войти **department / 123**. Выбрать слева **Аналитическая сводка**.
5. В форме предложения ввести название плана **Проба сводки**, критерий **Указаны источник и дата данных**, действие **Подготовить аналитическую сводку**, время и поддержку **Один час рабочего времени и обсуждение с руководителем**. Код проверяющего уже равен коду вошедшего руководителя. Нажать **Предложить план сотруднику**.
6. Выйти, войти **employee / 123**, выбрать слева **Проба сводки**. В ответ ввести **Прошу два часа на первую попытку** и нажать **Вернуть на доработку**. Статус — **На доработке**.
7. Выйти, войти **department / 123**, выбрать **Проба сводки**. В поле **Время и поддержка первого действия** ввести **Два часа рабочего времени и обсуждение с руководителем**, нажать **Сохранить уточнение**. Статус снова **Предложен**.
8. Выйти, войти **employee / 123**, выбрать **Проба сводки**. Ответ — **Согласовано**, кнопка **Принять план**. Статус — **Согласован**.
9. В **Предъявить работу** действие уже выбрано. **Что сделано** — **Подготовила первую сводку**. Вид — **Текст работы**. **Свидетельство** — **Источник — учебный реестр. В отчёт включены 12 записей.** Нажать **Отправить работу на проверку**. Видна попытка 1, критерий ожидает проверки.
10. Выйти, войти **department / 123**, выбрать **Проба сводки**. У попытки 1 выбрать **Нужна доработка**. Основание заключения — **Добавьте дату учебного реестра**. Нажать **Сохранить заключение**.
11. Выйти, войти **employee / 123**, выбрать план. Отзыв первой попытки виден. Новая работа — **Добавила дату данных**, свидетельство — **Источник — учебный реестр от 21.11.2026. В отчёт включены 12 записей.** Отправить. Видна попытка 2; первая и отзыв сохранены.
12. Войти **department / 123**, открыть план. У попытки 2 результат **Подтверждено**, основание **Источник и дата приведены, критерий выполнен**. Сохранить заключение. Критерий — **Подтверждено**.
13. В блоке завершения выбрать **Цель достигнута**, основание **Обязательный критерий подтверждён**, нажать **Зафиксировать итог**. План завершён.
14. Войти **employee / 123**, открыть план. Отметить критерий **Указаны источник и дата данных**, цель передачи — **Обсудить участие в проекте аналитики**, нажать **Подготовить пакет**. Отображён подтверждённый результат и сообщение, что передача получателю ещё не выполнена.
15. Обновить страницу, войти снова и открыть план. Согласованный план, две попытки, отзывы и итог остаются в БД.

Критическая отрицательная проверка — до шага 12 попытаться завершить план как «Цель достигнута». Сервер вернёт REQUIRED_CRITERIA_OPEN. После этой ошибки статус плана остаётся active.

## Объём

Форма первого предложения создаёт одно действие и один обязательный критерий. Чтение плана и проверка работ поддерживают несколько критериев/действий, полученных из API. Для доработки предложения можно изменить название и время первого действия. Произвольный конструктор критериев, каталог учебных возможностей и массовое изменение целей по новой ДИ относятся к дальнейшим частям продукта.

Текст работы сохраняется снимком, ссылка — с предупреждением об изменяемом внешнем источнике. Пакет выбранного результата сохраняется API, доставка другим модулям не выполняется. Экран не присваивает общий профессиональный уровень и не меняет кадровое назначение.
