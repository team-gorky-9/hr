# Подключённые пути сотрудников

В этой копии приложения доступны практика, материальная помощь и развитие сотрудника. Сохранены общие компоненты, шрифт, цвета и основной shell. Сервисы независимы, в интерфейсе явно показаны учебные роли или используется настоящая сессия Workforce.

## Открыть текущий запуск

- [Практика](http://127.0.0.1:19700/?workspace=practice) — публичное меню «Моя практика» или кнопка подачи на существующей витрине.
- [Материальная помощь](http://127.0.0.1:19700/?workspace=support) — «Сотрудник» → «Материальная помощь».
- [Развитие](http://127.0.0.1:19700/?workspace=development) — «Сотрудник» → «Развитие».

Точные поля, ввод, роли и ожидаемые исходы находятся в [STUDENTS.md](STUDENTS.md), [SUPPORT.md](SUPPORT.md) и [DEVELOPMENT.md](DEVELOPMENT.md). Проверенные данные синтетические, ответы получены через HTTP и сохраняются сервисами.

## Повторный запуск frontend

Из frontend выполнить npm ci, затем задать адреса нужных API и запустить npm run dev. В текущем локальном прогоне используются STUDENTS_API_TARGET=http://127.0.0.1:18505, SUPPORT_API_TARGET=http://127.0.0.1:18106, WORKFORCE_API_TARGET=http://127.0.0.1:18501. Для архива ARCHIVE_API_TARGET=http://127.0.0.1:18400.

Без переопределения proxy использует Students 8105, Support 8106, Workforce 8101, legacy 8000. Запуск каждого сервиса приведён в его README и модульной инструкции. В production те же пути должен обслуживать доверенный gateway.

Dev proxy распределяет /api/v1/students → Students, /support-api → Support /api/v1/support, /workforce-api → Workforce /api/v1. Более точный путь Students проверяется до общего /api/v1. Браузер не получает рабочие серверные секреты.

API ошибок не заменяются успешными демонстрационными ответами. Учебный selector роли Support/Students относится к fixture-режиму самих сервисов. Workforce использует вход через /sessions. Авторизацию рабочей установки следует подключать по существующим контрактам.
