# Материальная помощь через настоящий API

Раздел использует существующие Card, Btn, Badge и шрифты/палитру frontend. Компонент — src/components/support/SupportPage.tsx, клиент — src/api/support.ts. Вход приложения подключает владелец App. Путь API задаёт VITE_SUPPORT_API_BASE, по умолчанию /support-api. Proxy этого префикса должен направлять запросы в /api/v1/support сервиса Social support.

Сервис запускается из services/social-support командой uv run uvicorn support.main:app --host 127.0.0.1 --port 18106. В проверенном запуске SUPPORT_DATA_DIR=data-ui-check содержит отдельную SQLite и оригиналы. Встроенные опубликованные условия support-training-v1 и акторы fixture — учебные. Настоящий рабочий периметр/вход подключаются отдельно, в интерфейс не передаются рабочие секреты.

Данные формы и результаты идут через настоящий API. Подача фиксирует отдельный снимок, дополнение создаёт новую редакцию. Автор внешнего решения и секретарь, который его внёс, сохраняются отдельно. Личная выписка и исполнение читаются из публичной проекции сервера.

## Точная проверка

Подготовить два небольших текстовых файла на компьютере. application.txt содержит «Учебное заявление на помощь UI-SUPPORT». evidence.txt содержит «Учебное подтверждение обстоятельства UI-SUPPORT». Реальные личные документы для этого сценария не нужны.

1. Открыть раздел «Материальная помощь». Убедиться, что видна метка «API · учебные условия». В «Учебная роль» выбрать **Сотрудник**.
2. Нажать **Новое заявление**. В условиях выбрать **Учебная помощь А — не нормативный перечень**. В «Заявление» ввести **Учебное заявление UI-SUPPORT, прошу рассмотреть материальную помощь.** Нажать **Сохранить черновик**.
3. В поле загрузки **Учебное заявление** выбрать application.txt. Дождаться «Документ загружен». Нажать **Подать заявление**. Появится номер SP-… и статус «На проверке». Сохранить номер, чтобы выбирать то же дело при смене роли.
4. В «Учебная роль» выбрать **Координатор**, открыть это дело. В «Основание назначения» ввести **Учебное распределение UI-SUPPORT от 21.11.2026**. Нажать **Назначить проверяющего и секретаря**.
5. Выбрать **Проверяющий**, открыть то же дело. В «Источник кадрового подтверждения» ввести **Учебная кадровая запись UI-SUPPORT**. Нажать **Подтвердить по источнику**. Появится «Текущий статус — подтверждён».
6. В «Проверка комплекта» у заявления оставить **Принят**, у подтверждения — **Отсутствует**. В «Замечание — Учебное подтверждение» ввести **Добавьте учебное подтверждение**. В «Сообщение сотруднику» ввести **Просьба приложить evidence.txt**. Нажать **Сохранить проверку**. Статус станет «Нужно дополнить».
7. Переключиться на **Сотрудник**, выбрать дело. В «Сообщение по делу» видна просьба. Загрузить evidence.txt в поле **Учебное подтверждение**. В «Пояснение к дополнению» ввести **Направляю учебное подтверждение**. Нажать **Отправить дополнение**. Статус вернётся «На проверке».
8. Выбрать **Проверяющий**, открыть дело. В проверке комплекта оба файла отмечены «Принят». В «Сообщение сотруднику» ввести **Комплект принят, направлено на рассмотрение**. Нажать **Сохранить проверку**. Статус «Готово к рассмотрению».
9. Выбрать **Секретарь**, открыть дело. Результат — **Одобрено**. Заполнить «Объяснение сотруднику» значением **Учебное решение: помощь одобрена, исполнение подтверждается отдельно.**, «Реквизиты внешнего решения» — **UI-SUPPORT-2026-11-21**, «Автор внешнего решения» — **Учебная комиссия**, «Дата решения» — **21.11.2026**, «Основание регистрации» — **Учебная регистрация внешнего решения**. Нажать **Сохранить решение**.
10. Выбрать **Сотрудник**, открыть то же дело. В «Личной выписке» видны одобрение, дата и публичное объяснение. Рядом **Исполнение не подтверждено**. Внутренние реквизиты решения в личную выписку не входят. Обновить страницу и вновь открыть дело — запись сохраняется в SQLite.

## Продолжение до исполнения

Координатор назначает учебного исполнителя executor с основанием. Исполнитель записывает подтверждённое/неподтверждённое/ошибочное исполнение с источником, автором, датой и заметкой. Заявитель видит разрешённое состояние исполнения. Специалист закрывает дело с основанием. Запись решения сама по себе не отмечает выплату.

Изменения передают актуальный expected_revision. При конфликте сервер просит перечитать редакцию, кнопка «Обновить» перечитывает дело. Сетевая ошибка показывает сообщение, прежние демонстрационные данные не подставляются.
