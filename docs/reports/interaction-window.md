# Единое окно: серверная поставка, 21 ноября 2026

Реализованы композиция в Hiring, узкие SQL-страницы обоих источников, Q-ref, FeedbackReview и отзыв назначения. [Контракт](../contracts/interaction-window.md), [запуск](../modules/interaction-window.md). Исходная база `deed93a`; при публикации включены последующие совместимые изменения main. Отдельный UI окна и production identity в серверную поставку не входят.

## Проверенный путь

Изолированные учебные R1/A1/H1/H2, общие fixture-акторы HR/C1/C2/department. Сценарии используют настоящие FastAPI routes, domain-операции и SQLAlchemy. SQLite заменяет PostgreSQL JSONB/UUID и Identity; рабочие БД не затрагиваются. HTTP между Hiring и legacy проходит через ASGITransport к настоящему приложению, без заглушки предметных ответов. Сетевой отказ проверяется отдельно MockTransport.

Команда из корня продукта (PYTHONPATH содержит корень и services/hiring):

```text
python -m pytest --import-mode=importlib --noconftest -p no:cacheprovider -q -s tests/test_interaction_http.py tests/test_interaction_legacy.py services/hiring/tests/test_interaction_portal.py services/hiring/tests/test_interaction_window.py
```

Результат: **4 passed за 3,11 с**. Python 3.13.7, FastAPI 0.165.0, SQLAlchemy 2.0.58, pytest 8.4.2. Полный набор не запускался по указанию участника.

- Q1 → прочтение → дополнение → отдельный ready HR. C2 не получает чужое обращение. Загрузка файла меняет revision, сохраняя Q; старый/отсутствующий Q-ref нового запроса отклоняется. Кандидатская история не раскрывает внутреннюю связь и основания HR; исторический Q получает `basis_unknown`.
- Реальный POST feedback закрывает H1, оставляя H2 и этап A1 без изменений. Continue-waiting review повторяем; новое тело того же request_id запрещено. Новая версия feedback делает старый review недостаточным. Устаревший этап не сохраняет review/StageEvent; stage_changed сохраняет оба атомарно на проверенном переходе department_interview.
- Отзыв H1 запрещает старую ссылку и запись ответа, не отнимая доступ к H2 и общим разрешённым app/text. После отзыва обоих доступ исчезает. GET без gateway key запрещён; browser identity-заголовки не влияют на серверный mapping. Известный working ID не проходит training-gate.
- Секции имеют единый DTO, SQL-фильтрацию, подписанную пагинацию и явную полноту. При отказе legacy доступный портал возвращается как partial; кандидат не вызывает legacy. Нет mapping — not_linked; при отказе единственного применимого источника — 503 без старых строк/деталей ошибки.

Замер внутри HTTP-сценария: **8 чтений, максимум 39,4 мс, максимум 7 727 байт** после окончательного DTO. Это малый локальный synthetic набор и ASGI-транспорт, не нагрузочный или сетевой benchmark. Выбраны конфигурируемые стартовые пределы 1 с connect / 2 с read / 3 с overall, 256 КиБ на источник, 25 строк по умолчанию (до 100), с запасом относительно наблюдаемого объёма и коротким бюджетом ожидания интерфейса. При отказе источник не маскируется пустым списком.

## Область, не подтверждённая этим прогоном

Исполнение новой миграции и блокировки PostgreSQL под конкуренцией, запуск Compose-профиля, реальная сеть, большой корпус и визуальный UI окна не проверялись. Миграция 0014 добавляет поля/таблицы без удаления прежней истории; новые Q используют существующие JSON/events. Ветка sent_to_department использует прежнюю предметную логику с перенесённой наружу границей commit; отдельный её сценарий в короткий прогон не входил.

После команды клиент перечитывает первую страницу; после 409 не подменяет версию автоматически; после неопределённого результата POST повторяет только тот же request_id. Отключение окна не удаляет записи. Следующая поставка интерфейса использует состояния loading/partial/not_linked/empty/forbidden и этот API; производственные гарантии требуют отдельной проверки на целевой инфраструктуре.
