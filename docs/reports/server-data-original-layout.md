# Серверные данные в аналитике и карточке

База: frontend `7269c05`. Визуальный эталон: неизменённые компоненты PR96 / `5c68c06`.
Область — AnalyticsDashboard и карточка кандидата; кабинеты сотрудников не изменены.

## Данные

`GET /api/v1/analytics/dashboard` читает существующие записи за выбранные даты:
поступление — дата отклика, первичный разбор/этапы — события, интервью — held_at,
направление — handed_off_at. Все блоки используют одинаковую вакансию/контур/период.
Недели и источники больше не взяты из frontend-массива. Первое время ответа
и длительность интервью не рассчитываются при отсутствии источника; слоты сохранены
с сообщением «Будет добавлено позже». XLSX конструктора остаётся срезом явно выбранного
годового снимка, не выдаётся за выгрузку оперативного дашборда.

В карточке рекомендации читаются из cross-assessments: актуальные формально
подходящие варианты с открытыми вакансиями, без придуманных процентов. Гайд читается
для выбранного отклика; отсутствие гайда отличается от ошибки загрузки.
Психологические три плитки сохранены без одинаковых оценок и типа личности.

## Проверка

- TypeScript/Vite: сборка, 82 модуля. Есть предупреждение bundle >500 kB.
- Два адресных теста: фактическая дата события и граница МСК, источники, контур,
  вакансия, состояния передачи, department=403.
- Новый расчёт выполнен на PostgreSQL стенда в READ ONLY транзакции до публикации:
  01–21.11.2026 training — 13 поступлений, 2 интервью, 2 передачи, 4 недели, 6 вакансий.
  Это наблюдение на дату проверки, не ожидаемые константы.
- Локальная карточка py-9101 через реальные API: нет прежних статических баллов,
  отсутствие гайда показано, рекомендации читаются с сервера. Основная геометрия
  сравнена в браузере с неизменённым PR96, ключевые группы классов также сверены.
- Тексты и количество строк зависят от данных; это не попиксельная идентичность
  исходному примеру. Состояние всех экранов приложения этим отчётом не подтверждается.
