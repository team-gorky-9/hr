## Для интерфейса

`POST /api/v1/management/plans` → `id`. Экран руководителя использует `GET …/{id}/summary`, полная версия `GET …/{id}` — только для HR. Главные числа: `totals.nominally_covered_needs` и `totals.independent_covered_places` из `totals.places`, рядом — `warnings`. Конкретное распределение людей по потребностям не показывать: сервис его не возвращает.

## Ограничения

- Вход — только пакет, подготовленный HR. Реестр потребностей, архив и официальный резерв не подключены.
- Подтверждение личности и доступности контакта — заявление HR во входе, сервис их не проверяет.
- Представление для роли `department` и самоисключение руководителя не сделаны: по контракту это отдельная задача.
- Предполагаемые дубли без `person_ref` не склеиваются. Диапазон «со склейкой и без» из technical не считается: показывается только число `unresolved_records`.
