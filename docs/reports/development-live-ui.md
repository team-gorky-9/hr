# Интерфейс развития сотрудника

21 ноября 2026. База hr/main 5e7def8383ae02c29eb362a48e7d90ec9643ceab, ветка codex/development-live-ui. Использованы существующие Card, Btn, Badge, типографика и цвета фронтенда. Изменения ограничены компонентом развития, его API-клиентом и инструкцией.

DevelopmentPage получает настоящую сессию Workforce через логин и пароль. Цель, её передача, предложение плана, согласование, работа, заключение, итог и пакет результата записываются существующими API. API-клиент использует VITE_DEVELOPMENT_API_BASE либо /workforce-api. Родительская интеграция добавляет вкладку и dev-прокси к /api/v1 сервиса. Заглушки данных и серверные изменения не добавлялись.

Развилки реализации. Существующие goal/plan/submission/review операции позволили замкнуть один путь без нового контракта. Для первого предложения форма содержит одно действие и один обязательный критерий, чтение и проверка поддерживают несколько записей, полученных из API. Руководитель и проверяющий назначаются по коду учётки, поскольку каталог акторов доступен сервером только HR/admin. Код собственного пользователя показан для копирования. Токен хранится в памяти экрана, после обновления требуется повторный вход.

Проверка — одна сборка npm run build в отдельной копии и один браузерный прогон Chrome на объединённом интерфейсе http://127.0.0.1:19700/?workspace=development. Workforce http://127.0.0.1:18501, AUTH_MODE=workforce, отдельная SQLite development-ui.db после штатного prepare, seed employee/123 и department/123. PostgreSQL, брокер и полный набор тестов не запускались.

Браузерный прогон 1440×1060 занял около 7,5 с. Сотрудник создал личную цель и передал её руководителю. Руководитель предложил план, сотрудник вернул его с просьбой о двух часах, руководитель исправил ресурс, сотрудник принял. Первая работа возвращена с причиной, вторая подтверждена. Прежняя попытка и отзыв сохранены. Попытка закрыть reached до проверки получила серверный отказ. После подтверждения план закрыт и пакет выбранного результата подготовлен. Обновление страницы и повторный вход перечитали завершённый план и обе попытки. Ошибок JavaScript не было.

Точная инструкция с полями, значениями и кнопками — [frontend/DEVELOPMENT.md](../../frontend/DEVELOPMENT.md). Пакет результата имеет серверный статус not_sent. Доставка в другой модуль и общий профессиональный уровень сотрудника этим действием не создаются.
