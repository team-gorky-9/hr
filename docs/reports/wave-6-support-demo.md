## Повторить

Из `services/social-support`, PowerShell:

```powershell
uv sync --python 3.13 --dev
$env:WAVE6_REPORT_DIR = '../../docs/reports'
uv run pytest tests/test_wave6_demo.py -q -s
```

Один настоящий HTTP-путь с временными SQLite/оригиналами, отдельным uvicorn и его
перезапуском. Повтор создаёт новые ID. Переменная отчёта необязательна; с ней
перезаписываются [учебные запросы/ответы](wave-6-support-examples.json).
`requests` содержит акторов и входы (включая текст synthetic-файлов), `trace` —
статусы и JSON-ответы. Фактическое скачивание оригинала проверено сравнением байтов;
бинарный ответ не входит в JSON trace. Authorization/секреты в отчёт не пишутся.
Для показа по шагам использовать README запуска и `Bearer fixture:<actor>`, заменяя
ID и revision из примера фактически полученными ответами своего запуска.

## Один учебный пример

Правило `support-training-v1`, приложение DEMO-6B, все акторы и источники вымышлены.
Это проверка механизма, не утверждение прав на помощь или реальной выплаты.

| Участник | Действие | Наблюдаемый результат |
|---|---|---|
| `employee` | Создаёт дело, загружает только заявление, подаёт | Case `557339e3-010e-4b41-b946-7eeb075fee58`, снимок подачи с одним файлом |
| `coordinator` | Назначает специалиста и секретаря с учебным основанием | Доступ получают назначенные участники |
| `specialist` | Вручную регистрирует synthetic кадровый источник, возвращает комплект без evidence | `needs_information`, сотрудник видит «Добавьте учебное подтверждающее приложение» |
| `employee` | Загружает evidence и явно подаёт дополнение | Новый снимок с двумя файлами; первая подача с одним файлом сохранена |
| `specialist` | Проверяет новый состав | `ready_for_review` |
| `secretary` | **Вручную** регистрирует внешний учебный протокол `DEMO-6B`, автор — «Учебная внешняя комиссия» | `approved`, отдельный регистратор secretary; исполнение пока `unknown` |
| `employee` | Читает собственную выписку | Outcome `approved`, объяснение и дата; внутреннего протокола и оснований полномочия нет |
| `coordinator` → `executor` | Назначение регистратора → запись `unknown` | Личный результат сохраняет ожидание подтверждения |
| `executor` | **Вручную** регистрирует `confirmed` по synthetic accounting registry от учебного регистратора | Подтверждённый внешний факт, не платёж из приложения |
| `specialist` | Закрывает с явным учебным основанием | `closed`, `execution.status=confirmed`, в истории оба состояния исполнения |

Оригинал заявления `4a097437-4d50-449c-b9db-7a90dc455e87`;
дополнение `043f550b-c6f8-42a9-98fe-a6ce99d46b26`.
Решение и личная выписка этой версии имеют ID `6349ba22-378f-4a27-9e2c-f7655dd5c344`.
Совпадение ID не расширяет состав выписки: внутренние поля отфильтрованы API.
Сотрудник не видит служебных реквизитов исполнения или общих протоколов.

Запуск: **1 passed in 2.35s**, Python 3.13, SQLite, synthetic-данные.
Другой заявитель `employee2` получает **404** по ID дела и выписки; запрет на
выписку сохраняется после рестарта. После рестарта личная карточка и выписка
побайтно по JSON-значениям равны прочитанным до остановки, оригинал скачан с теми же байтами.
Публичная история также не содержит служебных `INTERNAL`-оснований.

## Браузер и зависимость интерфейса

Frontend `ecf5794`, Vite 6.4.6: выполнены `npm ci --no-audit --no-fund`,
`npm run dev -- --host 127.0.0.1 --port 5176 --strictPort`.
Через браузерный инструмент: «Сотрудник» → «Открыть: Забота и мотивация».
Фактически показаны психолог, арт-терапия, семейные события, спорт и обучение;
нет выбора вида материальной помощи, заявления, комплектности или личной выписки.

Сохранённое наблюдение дерева доступности:

```text
heading Забота и мотивация
text Поддержка, отдых и признание. Записаться можно в один клик, участие бесплатное.
button Психологическая поддержка; button Творчество; button Спорт; button Семья
heading Мои записи; text Вы записаны Групповая сессия с психологом · четверг, 18:00
heading Мои награды
```

По коду `frontend/src/components/employee/Care.tsx` — локальные `items` и `booked`,
не клиент `/api/v1/support`. Готовность пользовательского пути не подтверждена.
Следующий потребитель Маша/Ася: [OpenAPI](wave-5d-support-openapi.json), `requests/trace`
этого прогона и роли выше достаточны для подключения подачи, дополнения и личного
результата. Отдельно показать ожидание `unknown`; не подписывать одобрение как выплату.

Рабочий показ требует внешних подтверждений: действующее правило помощи,
кадровый источник и назначенные полномочия, оригинальный итог комиссии с автором,
свидетельство исполнения с внешним источником. Здесь все четыре основания synthetic.
Не проверялись рабочие данные, PostgreSQL, единый вход, бухгалтерская интеграция,
доставка уведомлений и нагрузка. Полный набор не запускался по режиму шестой волны.
