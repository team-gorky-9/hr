# Live recruitment frontend

2026-11-21. Existing desktop vacancy list, application card, telephone interview and department cards now use the legacy API. No mock success or fallback candidates remain in these four screens. CandidateCard receives an application UUID in its existing candidateId prop. TelephoneInterview requires applicationId from the same selection. App/vite integration belongs to the integration branch.

Configuration: VITE_RECRUITMENT_API_BASE defaults to /legacy-api/api/v1, VITE_RECRUITMENT_CONTOUR defaults to training, VITE_RECRUITMENT_HR_LOGIN defaults to hr_demo, VITE_RECRUITMENT_DEPT_LOGIN defaults to dept_demo. VITE_RECRUITMENT_RECIPIENT_ID must identify the actual department account. These are labelled training accounts, not Workforce SSO. No directory endpoint exists in the current contract; this demonstration uses one configured recipient.

Implemented: vacancy/application reads, anonymized detail/source and exact UTF-16 evidence highlighting; history and reason references; explicit stage decisions with expected_seq and confirmation for skips; summary preview before handoff; handoff creation, deadline extension with reason, persisted department feedback and corrections, HR reread; guide read/create, versioned answer writes and explicit interview outcome. Buttons disable after terminal stages. Errors preserve the server message and allow reread. Department access is determined server-side by its own role header.

Validation: npm run build passed (TypeScript + Vite 6.4.6). A first local invocation had no node_modules; the successful invocation reused installed dependencies from the integration clone. No browser/manual QA was performed, per the user's instruction.

Limitation observed: POST interview-guide on this runtime returns 500 INTERNAL_ERROR. Current search-demo records have no approved assessment/profile. The UI exposes the server failure; guide generation, answer persistence and interview outcome have code integration but were not proven on this runtime. New assessment/profile preparation or backend configuration is a separate prerequisite. Upload/import, arbitrary recipient directory and automated invitation delivery are not available through these legacy endpoints. Department reason options use existing seeded codes experience/other because the references route is staff-only.
