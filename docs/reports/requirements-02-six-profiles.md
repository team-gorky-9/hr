## Обнаруженные ошибки и ограничения

В дополнительном примере до исправления фраза «В тестировании ПО опыта нет» возвращала `unknown`. Причина — отсутствие варианта отрицания с ведущей областью деятельности. Исправлен распознаватель, добавлены положительные и отрицательные случаи; версия вычислителя **assessment-2.0.3**. Результаты прежней версии будут stale. Профильная политика и контракты не менялись.

В предыдущем полном запуске `6cc99de3` было 705 passed, 1 failed, 1 skipped и 3 subtests: `test_reporting.py::test_idempotent_concurrent_and_correction` получил Windows `PermissionError` при чтении одновременно записываемого файла. Код отчётности не меняли. Отдельный повтор этого теста прошёл, итоговый полный повтор тоже прошёл. Однократный сбой остаётся известной нестабильностью проверки на Windows; успешный повтор не доказывает устранение её причины.

Единственный пропуск финального прогона — `tests/test_reporting_management_api.py:220`, проверка JavaScript SDK: Node.js отсутствует в окружении. Docker/PostgreSQL 17, качество живой LLM на реальных резюме, автоматический ФРДО и актуальность правовых норм отдельно не проверялись. Источник данных этой задачи — реальные ДИ/матрица; отклик для контрольного сравнения — синтетический.

Рабочие профили **не утверждены**. Тестовые approve выполнялись внутри откатываемых транзакций с тестовым актором. Для эксплуатации активный HR/admin должен отдельно подтвердить конкретную версию с основанием; затем потребители получают её UUID.
