# Архивное повторное рассмотрение через UI

21 ноября 2026. База e7d507f0085e651b484488d50e7330d00dd5a0cf, отдельная ветка codex/archive-reconsideration-live. Пользователь поручил сразу frontend с настоящими endpoints, сохранив текущий дизайн. Для отсутствующего endpoint разрешено использовать уже готовую техническую функцию.

Добавлен раздел «Архив резюме» по существующим таблице, карточке, полям и кнопкам. Поиск, источник, история, подборка и новое рассмотрение используют HTTP. Новый POST /api/v1/archive/reconsiderations вызывает repository.create_application и сохраняет подтверждение HR в первом событии истории. Остальной frontend не переносился с прежних экспериментальных веток.

Проверка на отдельной PostgreSQL 16 с pgvector. Контейнер codex-archive-live-db, локальный порт 15439, БД archive_demo. Миграции 0001–0013 прошли. Штатный app.search load-demo создал 18 синтетических записей. API app.main на 18400, Vite с ARCHIVE_API_TARGET=http://127.0.0.1:18400 на 18417.

HTTP-прогон scripts/check_archive_live.py проверил поиск BPMN, чтение источника search-9001, сохранение основания контакта, явное подтверждение, создание нового отклика, повтор с прежним ID, 403 для department, авторство в истории и неизменность прежних этапов.

Playwright + Chrome, desktop 1440×1040. Через браузер выбран search-9002 по запросу «44-ФЗ», записано основание контакта, введено согласие и создан отклик 76475bf0-ea51-4546-a4e2-a08a76d6ca76. Настоящие ответы HTTP: поиск/источник/чтение подборки 200, сохранение подборки и нового отклика 201, история 200. После обновления вкладки подборка и рассмотрение прочитаны из БД. Пустой запрос по отсутствующему опыту дал 0 результатов, искусственный обрыв соединения показал ошибку без старой выдачи. Ошибок JavaScript не было. npm run build (TypeScript + Vite) прошёл, 64 модуля.

Скрипт HTTP рассчитан на отдельный учебный набор и выбирает вакансию, где у контрольного кандидата ещё нет отклика. Для повтора нужен доступный новый целевой вариант. Запуск с производственной БД запрещён назначением этого примера.

Границы результата: подключён настоящий API на синтетических данных. Рабочая авторизация и периметр устанавливаются доверенным шлюзом. Доставка приглашений не реализована, фиксируется согласие, полученное через внешний канал. Повторное открытие уже завершённой пары кандидат–вакансия не выполняется, endpoint возвращает существующую запись. Поисковый API отдаёт код записи, имя и контакты не подставляются из фикстур интерфейса.
