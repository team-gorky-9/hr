# Волна 2 · внутренняя публикация вакансии

Дата: 21 ноября 2026. Ветка feature/wave-2-vacancies, база 0a20c84. Контракт: ../contracts/wave-2-stage-1.md. Задача: https://github.com/team-gorky-9/hackaton/blob/main/hq/tasks/stage-1/wave-2-denis-vacancies.md.

Реализованы семь операций каталога, история редакций в HR GET, проверка организации/подразделения/approved-профиля, текущей версии при публикации, expected_revision, запрет изменения опубликованного объявления. Новая миграция не меняет таблицы legacy. Исходные файлы и профиль сохраняют прежний контракт. Перед запуском выполнить `uv run alembic upgrade head` из services/requirements.

Проверка из корня hr: `uv --directory services/requirements run pytest tests/test_vacancies.py tests/test_stage1.py -q -s` — 2 passed. Реальный HTTP отдельного uvicorn, SQLite, миграции 0001→0002, учебные fixture-акторы без RabbitMQ/Workforce. Первый сценарий проверяет каталог, второй — совместимость прежнего пути v1/v2 и рестарт процесса. Полный набор не запускался согласно текущему режиму короткой проверки.

Вход: department_id=00000000-0000-4000-8000-000000000011, position_code=economist-training, title=Экономист, description=Учебная вакансия: финансовые таблицы. Через API требований получен approved profile f032edd4-d458-4713-a03d-fd8430a56356 (источник 90f9dee8-7979-414d-8fde-631ffe1b3a6a). POST /api/v1/catalog/vacancies создал c321f26a-e5ec-458a-8883-ad12bb0297f8. PATCH изменил title; publish включил запись в публичный список; close с причиной исключил её. GET карточки показал revision=4, status=closed и четыре снимка истории с исходным текстом.

Критичные отказы: чужая организация — 404; employee — 403; неизвестное подразделение, пустая причина — 422; ID черновика вместо approved — 404; устаревшая форма и правка опубликованной записи — 409. После утверждения следующего профиля публикация черновика со старым profile_id даёт PROFILE_NOT_READY без изменения revision; явный PATCH нового profile_id позволяет публикацию. Публичные ответы проверены на точный набор пяти полей.

Ограничения: PostgreSQL/Docker не запускались; внешняя публикация, автоматический подбор, брокерная доставка, потребность с количеством и фронтенд не входят в задачу. Маша/фронтенд могут использовать /openapi.json и тестовый пример после запуска сервиса. История доступна только HR/admin в GET /api/v1/catalog/vacancies/{id}.
