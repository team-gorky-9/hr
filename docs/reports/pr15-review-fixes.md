# Исправления замечаний ревью PR #15

20.11.2026. Ветка `feature/profile-assessment-integration`. Получены изменения Ильи до `a2b840c`; локальная регрессия сохранённого ответа FormalExtraction объединена с ними в `860a1d8`. Итоговый алгоритм — `assessment-2.0.2`, промпт — `assess-v4`.

## Исправлено

| Дефект | Теперь |
|---|---|
| Команда approve создавала неизвестного пользователя с ролью HR и могла утвердить рабочий профиль | Требуется уже существующий пользователь. Repository проверяет роль и активность. Отказ не создаёт пользователя и не меняет профиль; одинаково для обоих контуров и обоих способов выбора профиля. |
| «Опыт работы не указан. Диплома нет.» давало not_met | Отрицание ограничено фразой об опыте. Отсутствие описания и отрицание другого предмета не означают отсутствие опыта. |
| Перестановка цитат образования меняла met на unknown | Направление проверяется внутри каждой цитаты, без искусственного склеивания соседних фрагментов. |
| Одинаковые альтернативы теряли список quotes | Объединяются все цитаты с контекстом. Разные статусы требуют исправления моделью; разные непустые цитаты индикатора также, поскольку у него одно поле quote. |
| Неверный ключ из ответа модели попадал в журнал ошибок | Наружная диагностика содержит тип ошибки и путь из известных полей схемы; неизвестные имена заменены маркером. Текст validator и входные значения не журналируются. |
| Оценка старого промпта отображалась ready при совпадении алгоритма | API проверяет обе версии; несовпадение, в том числе null, даёт stale/algorithm_changed. Версия алгоритма повышена для пересчёта старых результатов. |

Например, модель выделила «Опыт работы не указан. Диплома нет.» как отсутствие опыта. Оценщик находит цитату в резюме, но теперь не принимает отрицание диплома за отрицание опыта: целевой результат — unknown, без свидетельства not_met. API сохраняет необходимость уточнения вместо ложного невыполнения требования. Само извлечение смысла остаётся задачей модели; ограниченная проверка явных формулировок не является универсальным анализатором русского языка.

## Переход

У команды approve удалён `--approver-name`: подготовка пользователей — отдельная административная операция, `app.db.seed` пользователей не создаёт. `--approver` указывает существующего HR/admin; это служебная команда доверенного оператора БД, не аутентификация пользователя. Рабочие профили при этой проверке не утверждались. Старые оценки становятся stale; их пересчёт не запускается автоматически. Публикация этих исправлений и слияние в main в данный шаг не входят.
