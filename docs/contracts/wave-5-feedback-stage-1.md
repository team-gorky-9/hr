# Волна 5 · обратная связь · этап 1

Четыре самостоятельных результата Давида в отдельной области employee-feedback. Общие механизмы очередей и внешняя модель не требуются. Пульс и именное обращение имеют разные данные и права. Префикс /api/v1/feedback, учебный контур явно обозначен.

## Общие условия

Ресурсы управления имеют UUID, revision и серверного автора. Изменение принимает expected_revision, неправильное состояние — 409, неверный вход — 422, чужой объект — 404. Для пульса ответ не получает actor_id, IP, user-agent, точное время подачи, код приглашения или ссылку на личное обращение.

Первый путь пульса — оценки фиксированных вопросов и выбор одной темы из опубликованного списка. Свободное описание личной проблемы доступно через отдельное конфиденциальное обращение 5D. Автоматический анализ текстов и психологические выводы не входят в эту поставку.

Учебный доступ — одноразовые случайные коды для группы без соответствия человеку. Организатор раздаёт их вне системы. API ответа не требует личной сессии и не использует cookie/Authorization для связи ответа. Код передаётся в теле, не в URL. В прикладном хранении связи кода с ответом нет. Связывание по внешним сетевым журналам или наблюдению оператором этим механизмом не устранено, абсолютная анонимность не заявляется.

## 5A · цикл и ответы

Cycle = {id,organization_id,title,question_version,questions:[{key,text,min,max}],topic_options:[{key,label}],groups:[{key,label,eligible_count}],status:draft|open|closed,revision}. Группы — фиксированные непересекающиеся учебные группы. Шкалы валидируются в опубликованном диапазоне, вопросы/группы после открытия неизменяемы.

| Операция | Результат |
|---|---|
| POST /cycles | Назначенный организатор создаёт цикл |
| POST /cycles/{id}/open {expected_revision} | Фиксирует версию и открывает приём |
| POST /cycles/{id}/access-codes {group_key,count} | Организатор получает случайные коды без person map; хранятся digest, цикл, группа и used boolean |
| GET /cycles/{id}/form | Публичная форма без списка участия и внутренних ответов |
| POST /cycles/{id}/responses {access_code,answers:[{question_key,value}],topic_key} | Атомарно расходует код и сохраняет ответ с циклом/группой, случайным ID, оценками и темой |
| POST /cycles/{id}/close {expected_revision} | Закрывает приём |

Для использованного кода не сохранять response_id или точный used_at. Ответ не содержит code digest. Обе записи сохраняются одной транзакцией. Повтор — 409 CODE_ALREADY_USED без предыдущего ответа. Payload, код, cookie и содержание ответа исключены из прикладных логов/аудита. API первичных ответов для HR/руководителя отсутствует.

Общее количество выпущенных кодов группы не превышает frozen eligible_count. Дополнительная выдача проверяет остаток атомарно; персональный журнал распределения кодов не ведётся. Код выдаётся в ответе один раз, в хранилище остаётся digest. Для закрытия повторной сетевой отправки пользователь получает факт «код использован» без ссылки на содержание прежнего ответа. Возвращать код или ответ через идентифицирующий диагностический журнал нельзя.

До расходования кода проверить полный состав уникальных question_key, диапазоны шкал и допустимую тему. Ошибка ввода не расходует код. Группа определяется кодом, её нельзя выбрать другим полем запроса. Повтор выпуска публикации с теми же параметрами возвращает существующий ID; изменение параметров уже выпущенной публикации отклоняется.

Демо — открыть цикл, ответить по коду, повтор получить отказ; в сохранённом ответе отсутствуют поля личности и связи с кодом. Это адресная проверка функции, без заявления полной сетевой анонимности.

## 5B · фиксированная публикация

POST /cycles/{id}/publication {expected_revision,policy:{k:int>=2},policy_basis} выполняет назначенный ответственный после закрытия. В учебном примере k=5, это демонстрационный параметр; рабочее правило подтверждает владелец.

Публикуется одна фиксированная таблица непересекающихся групп, без произвольных фильтров и общего итога. Категории шкал/тем имеют shown/suppressed. При менее k ответах группа скрывается. В демонстрационной политике также скрывается группа, где ответивших больше eligible_count-k, чтобы не показывать участие всей малой группы.

Малые категории скрываются. Если известное число ответов и остальные ячейки позволяют вычислить скрытую, скрывается дополнительная ячейка или вся строка. В первой поставке допустимо скрыть целую строку при неоднозначности. В публикации нет первичных ответов, цитат, точных времён и списка ответивших. Значение suppressed не отдаётся скрытым JSON-полем.

GET /publications/{id} выдаёт сохранённую таблицу разрешённой роли своей области. Руководитель читает свою допустимую группу, организатор — разрешённый выпуск. Прав на первичные данные это не даёт.

Первый выпуск неизменяем. Второй по тому же циклу в этом пути не формируется, чтобы не создавать необработанный канал разности публикаций. Исправление методики и перевыпуск — отдельная задача. Защита от всех способов косвенного определения автора не заявляется.

Демо — достаточно большая группа получает допустимые ячейки, малая скрыта, дополнительный произвольный срез недоступен. Порог и область политики указаны у выпуска.

## 5C · мера и ответ сотрудникам

Measure = {id,publication_id,group_key,topic_key,text,owner_actor_id,due_on:null|date,status:planned|in_progress|completed|cancelled,revision,outcome_note:null|string}. POST /measures создаёт руководитель своей опубликованной группы либо уполномоченный организатор. PATCH /measures/{id} принимает revision, состояние/пояснение; завершение и отмена требуют причины. GET /measures возвращает разрешённые меры.

POST /publications/{id}/participant-message {text,measure_ids} публикует организатор для всей приглашённой аудитории группы. GET /cycles/{id}/outcome возвращает доступный итог. Рассылка только ответившим не используется; списка ответивших у продукта нет.

По теме может быть открыта общая инициатива. Конкретные люди не отбираются по их ответам. Сравнение со следующим циклом учитывает версии вопросов, групп и политики; при несовпадении показывает несопоставимость. Новый цикл создаётся отдельно, автоматический причинный вывод не строится.

Демо — по теме создана мера, затем результат и сообщение всей группе. Сотрудник видит, что сделано, независимо от участия в опросе.

## 5D · конфиденциальное обращение

ConfidentialCase = {id,author_actor_id,organization_id,recipient_actor_id,subject,text,revision,status:submitted|in_progress|answered|closed,reply:null|string}. Автор знает адресата до отправки. Получатель назначен организацией для этой области.

POST /confidential-cases создаёт собственное обращение employee. GET /confidential-cases и GET /confidential-cases/{id} доступны автору и конкретному получателю. POST /confidential-cases/{id}/reply {expected_revision,text} отвечает получатель. POST /confidential-cases/{id}/close {expected_revision,reason} закрывает автор/получатель с историей. HR/admin без отдельного назначения содержания не читает.

Связь с ответом пульса не хранится. Переход из группового итога — новое явное обращение. Это не специализированный режим экстренной помощи. Получателя и сроки ответа определяет организация; в учебном примере они обозначены.

Демо — обращение, ответ адресата, чтение автором, отказ обычному руководителю в прямом чтении. Exit-опрос — последующая отдельная карточка.
