# Контракт поиска кандидатов по профессиональному опыту

Версия 1.0 для `search-01`. Маршрут `POST /api/v1/search/candidates` ищет профессиональный опыт в текущем очищенном резюме и возвращает проверяемые основания. Дата, заголовок отклика и текущий этап служат контекстом. Балл поиска описывает порядок выдачи. Применение требований должности остаётся в API оценки.

## Доступ и вход

`Content-Type: application/json`. `working` (по умолчанию) читает только `candidates.is_synthetic = false` в выделенной БД установки. Рабочий маршрут требует `Authorization: Bearer <HR_SEARCH_WORK_TOKEN>`, который на рабочем стенде добавляет доверенный серверный прокси после проверки кадрового доступа. Секрет хранится на серверной стороне. Пустая настройка, отсутствующий или неверный ключ дают одинаковый `401 SEARCH_AUTH_REQUIRED`. `training` выбирается явно, читает только `is_synthetic = true` и доступен без поискового ключа. Контур и право применяются до чтения резюме и отбора в обеих ветках. Схема установки едина для одной организации, а доступ к существующим `/applications` и `/candidate-texts` защищает общий периметр продукта. Заголовки, заметки, `raw_text`, ПДн, векторы и поисковый ввод в ответе отсутствуют. `Cache-Control: private, no-store` для успешных ответов.

```json
{
  "query": "анализ и согласование требований к ИС",
  "contour": "training",
  "limit": 10,
  "filters": {
    "skills": [],
    "skill_match": "all",
    "education_levels": [],
    "in_reserve": null,
    "required_terms": []
  }
}
```

| Поле | Допустимые значения и семантика |
|---|---|
| `query` | Строка, максимум 512 символов, по умолчанию `""`. Внешние пробелы игнорируются. Строка из пробелов эквивалентна отсутствию запроса. Непустой текст должен содержать хотя бы букву или цифру. |
| `contour` | `working` или `training`. |
| `limit` | Целое `1…50`, по умолчанию `10`. Применяется после объединения по `candidate_id`. |
| `filters.skills` | До 20 непустых строк по 80 символов. Сравнение через `repository.normalize_skill` с навыками из текущей карточки, построенной из текущего текста. Дубли считаются один раз. |
| `filters.skill_match` | `all` (по умолчанию) или `any`. Без `skills` поле не задаёт условие. |
| `filters.education_levels` | До четырёх значений `EducationLevel`: `высшее`, `неоконченное высшее`, `среднее профессиональное`, `среднее общее`. Совпадение с любым из указанных уровней по `candidate_cards.education_level` (основное образование). Отсутствующий уровень или карточка от предыдущей версии текста условие не выполняют. |
| `filters.in_reserve` | `true` — есть запись со `status=active` и `valid_until=null` либо `valid_until >=` московской календарной дате запроса. `false` — такой записи нет. `null` — любое состояние. Должности и направления учитываются одинаково. |
| `filters.required_terms` | До 12 непустых строк по 80 символов, каждая содержит букву или цифру. Все термины должны подтвердиться в профессиональных фрагментах того же текущего текста. Термины могут совпасть в разных фрагментах. Исключённые участки резюме не участвуют. |

Объект `filters` по умолчанию пуст. Неизвестные поля и неверные типы дают `422`. Все заданные виды фильтров пересекаются. На входе нужен запрос или хотя бы одно действующее условие. Без запроса, с одними условиями, возвращаются прошедшие кандидаты. При наличии фразы кандидат должен пройти условия и иметь поисковое совпадение. Ноль совпадений возвращает `200` и `items: []`.

Точное совпадение использует регистр без различий, NFKC, `ё/е`, нормализацию пробелов и вариантов дефиса, включая пробелы вокруг дефиса в кодах. Цифровые и технические токены сохраняются целиком: `44‑ФЗ` совпадает с `44-ФЗ`, `C++` и `1С` сопоставляются по границам токена, `144-ФЗ` не совпадает с `44-ФЗ`. Латинская `C` и кириллическая `С` остаются разными буквами. Многословный обязательный термин совпадает как последовательность целых токенов. Прямое отрицание того же навыка в коротком обороте (`не работал с C++`, `нет опыта с ЕИС`, `без опыта 44-ФЗ`) не считается положительным упоминанием. Правило ограничено указанными конструкциями и ближайшей фразой.

## Успешный ответ

```json
{
  "contour": "training",
  "mode": "hybrid",
  "semantic_status": "ready",
  "items": [
    {
      "candidate_id": "66666666-6666-4666-8666-666666666666",
      "candidate_code": "search-9001",
      "score": 0.01639344262295082,
      "match_kind": "semantic",
      "evidence": {
        "candidate_text_id": "11111111-1111-4111-8111-111111111111",
        "chunk_kind": "experience",
        "fragment": "Сбор функциональных требований к СЭД, BPMN, постановка задач подрядчику.",
        "start_offset": 14,
        "end_offset": 86,
        "utf16_start": 15,
        "utf16_end": 87
      },
      "matched_required_terms": [],
      "filter_matches": [],
      "in_reserve": false,
      "applications": []
    }
  ]
}
```

Пример формата иллюстративный. Очистка дала `🧩\nОпыт работы\nСбор функциональных требований к СЭД, BPMN, постановка задач подрядчику.`. Клиент открывает `GET /api/v1/candidate-texts/11111111-1111-4111-8111-111111111111` и применяет `text.slice(utf16_start, utf16_end)`. Границы полуоткрытые, `start_offset/end_offset` отсчитаны в Unicode code points от начала всего документа. `chunk_kind`: `experience | skills | education | about | cover_letter | full`. История общения и подвал публикации исключаются при нарезке даже в `full`.

- `mode: hybrid | lexical | filters`. `hybrid` означает, что плотная ветка доступна хотя бы для части допустимых профессиональных фрагментов, независимо от числа совпадений. `lexical` сообщает, что смысловой поиск недоступен, а лексический выполнился. `filters` используется при пустом `query`.
- `semantic_status: ready | partial | unavailable | not_requested`. `ready` означает полный активный индекс в области запроса или пустую область при доступной конфигурации. `partial` означает, что часть фрагментов актуально проиндексирована. При отсутствии модели, ошибке её запуска или нулевой применимой векторной выдаче из-за отсутствия индекса в непустой области — `unavailable`. Для `filters` статус `not_requested`. На `partial` UI может обозначить неполный индекс. При `unavailable` UI показывает, что сейчас выполнен поиск по словам.
- `match_kind: lexical | semantic | hybrid | exact | filters`. Первые три значения обозначают источники ранга кандидата. Если две ветки подтверждают разные фрагменты кандидата, `hybrid` всё равно указывает на их участие, `evidence` показывает один лучший фрагмент. При пустой фразе с `required_terms` тип `exact`, `score: null` и фрагмент с максимальным числом обязательных совпадений. При остальных фильтрах без фразы тип `filters`, `score: null` и `evidence: null`. Список `matched_required_terms` использует уникальные значения входа в порядке ввода.
- `filter_matches[]` содержит только сработавшие структурированные условия. `{ "kind": "skills", "source": "candidate_skills", "values": ["python"] }`, `{ "kind": "education", "source": "candidate_cards.education_level", "values": ["высшее"] }` или `{ "kind": "reserve", "source": "reserve_entries", "values": [true] }`. Для запроса `in_reserve: false` последнее поле равно `[false]`. Отсутствие структурированных условий даёт `[]`.
- `applications[]` содержит реальные записи этого `candidate_id`. Поля объекта `application_id: UUID`, `source: response | history | manual`, `vacancy_id: UUID | null`, `position_id: UUID | null`, `position_title: string | null`, `posting_title: string | null`, `external_position_title: string | null`, `applied_at: YYYY-MM-DD | null`, `stage_code: string`, `is_active: boolean`. Карточка отклика открывается через `GET /api/v1/applications/{application_id}`. `is_active` истинно для `response` или `manual` на открытой вакансии с нефинальным этапом (`selection_stages.is_final=false`). У `history` оно всегда ложно. Архивный `posting_title` и назначенная штатная `position_title` передаются отдельными полями. Выдача без откликов использует `applications: []` и позволяет открыть исходный очищенный фрагмент.
- Одна строка на `candidate_id`. Хранимые повторные отклики по этому идентификатору показываются отдельно внутри `applications`. Разные `candidate_id`, которые на самом деле принадлежат одному человеку, остаются отдельными строками до внедрения склейки дублей. Сортировка по рангу с устойчивым разрешением равенств по `candidate_code`, при поиске только по фильтрам по `candidate_code`.

Пример запроса только по фильтрам для серверного прокси `{"filters":{"skills":["Python","FastAPI"],"skill_match":"all","in_reserve":true}}`. Для двух обязательных кодов `{"query":"муниципальные закупки","filters":{"required_terms":["44-ФЗ","ЕИС"]}}`. Пример пустой, но выполненной выдачи `{"contour":"training","mode":"hybrid","semantic_status":"ready","items":[]}`.

## Ошибки

| HTTP | `error.code` | Когда |
|---|---|---|
| `401` | `SEARCH_AUTH_REQUIRED` | Рабочий запрос без действующего серверного ключа. |
| `422` | `VALIDATION_ERROR` | Неверный JSON/тип/значение либо пустой запрос без условий. Стандартный `details.errors[]` с `loc`, `msg`, `type`. |
| `503` | `SEARCH_UNAVAILABLE` | PostgreSQL или поисковое чтение недоступны. Недоступность только энкодера отображается в успешном ответе с лексической веткой. |
| `500` | `INTERNAL_ERROR` | Непредвиденный серверный сбой. |

```json
{"error":{"code":"SEARCH_AUTH_REQUIRED","message":"Требуется доступ к рабочему поиску","details":{}}}
```

Клиент различает пустую выдачу, неполный/недоступный смысловой индекс и ошибку транспорта по HTTP-статусу и полям ответа.
