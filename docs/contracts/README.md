## Правила изменения контрактов

Функциональные части пятой волны — [пульс и конфиденциальное обращение](wave-5-feedback-stage-1.md), [социальная поддержка](wave-5-support-stage-1.md), [внешний кандидат](wave-5-candidate-portal-stage-1.md). Все новые операции здесь специфицированы к реализации.

Следующие функциональные части четвёртой волны — [признание и мероприятия](wave-4-motivation-stage-1.md), [мобильность](wave-4-mobility-stage-1.md), [кадровая картина](wave-4-reporting-stage-1.md). Это спецификации предстоящих небольших поставок с самостоятельными входами.

Третья функциональная волна разбита на короткие последовательные части — [развитие](wave-3-development-stage-1.md), [практика](wave-3-students-stage-1.md), [двунаправленный подбор](wave-3-matching-stage-1.md). Это спецификации будущей реализации. Поставки предыдущих волн для этого планирования не пересматривались.

Текущий объём Requirements и Hiring уточнён в [этапе 1](wave-1-stage-1.md). Workforce принят через #38, функциональный Hiring — через #39. Автоматический обмен Hiring/Workforce остаётся отдельным этапом. Прежние подробные контракты используются с этой явной границей.

Спецификации первой волны — [общие правила](wave-1-common.md), [Workforce · Давид](wave-1-workforce.md), [Hiring · Илья](wave-1-hiring.md), [Requirements · Денис](wave-1-requirements.md) и [учебные примеры](../../fixtures/wave-1/README.md). Реализованный объём сверяется с отчётами сервисов и профилем этапа 1.

Следующие небольшие задачи специфицированы в [волне 2, этапе 1](wave-2-stage-1.md) — вводная программа, итог телефонной встречи и внутренняя публикация вакансии. Эти новые операции предстоит реализовать.

1. Общий контрольный пример для сквозной сверки всех контрактов — синтетический отклик **`py-9001`** на вакансию `python-dev` (базовый текст: `Написал API-тесты для сервиса заявок.`).
2. Необязательные поля расширяют JSON. Новые значения enum требуют проверки клиентов с исчерпывающими ветками; совместимость не предполагается автоматически.
3. Удаление/переименование поля, изменение семантики ошибки или сигнатуры функции — несовместимое изменение: согласуется с Родионом и затронутыми владельцами на примере `py-9001` до слияния PR.
4. Описание внутреннего устройства каждого модуля его владелец поддерживает в `docs/modules/<модуль>.md`.
