# Модуль «Гайд интервью»

Из сохранённой оценки отклика — вопросы для звонка кадровика. Код — `app/interview/`. Контракт — [interview.md](../contracts/interview.md) v0.1 (проект). Задача — `interview-01` в штабе.

**Статус:** расчёт гайда готов (сборка пробелов, генерация уточнений и ядра, предпросмотр в CLI). Хранения гайда, ответов, рубрики и HTTP-маршрутов пока нет — их делает модуль БД и API после согласования контракта.

## Как устроено

1. `gaps.assemble_gaps` — **без модели**. Пробелы берутся из:
   - формальных проверок `screening` с результатом `unknown`;
   - индикаторов без сведений (по одному пробелу на компетенцию, группа `same_as` — одна единица);
   - групп с ручной сверкой.

   Слово из `card.missing` присоединяется источником к пробелу того же вида требования. Предварительный вывод по документальному требованию попадает в `document_requests`. Приоритет: обязательное требование → обязательный индикатор → желательное требование → желательный индикатор. Первые `budget` (по умолчанию 6) идут в генерацию, остальные — в `uncovered_gaps`. `gap_ref_id` — хеш ключей строк профиля, поэтому при переоценке пробел сохраняет id.
2. `generate.generate_clarifications` — один вызов модели на гайд. Модель получает заголовки пробелов, критерии `acceptance` и уже найденные цитаты, но **не текст резюме**. Ответ проверяется: только запрошенные ключи, каждый один раз; иначе одна просьба исправить, затем ошибка. Нет пробелов — нет вызова.
3. `generate.generate_core` — вопросы по строкам профиля этапа `interview`, пачками по 12. Их генерируют один раз на версию профиля. Готовую рубрику передают в `build_guide(core_cache=…)`: тогда у всех кандидатов одинаковое ядро и нет повторных вызовов.
4. `service.build_guide` собирает `GuideDraft` по полям контракта и пишет вызовы модели в `audit_log`. Сам ничего не сохраняет и не делает commit.

## Итог телефонной встречи (wave-2)

Кадровик завершает звонок действием `POST /api/v1/interviews/{id}/outcome`: `continue`, `stop` или `no_answer`, время и пояснение. Сохраняются дата, кто звонил и время записи сервером. Прочитать итог можно через `GET /api/v1/applications/{id}/interviews`. Гайд и записанные ответы встречу сами не завершают. Итог не меняет этап отклика. История записи хранится в `audit_log` (`event = interview.outcome_recorded`). Поля и коды ошибок описаны в [контракте](../contracts/interview.md#итог-телефонной-встречи-wave-2-миграция-0010).

Проверка через HTTP на учебной базе, модель не вызывается:

```bash
uv run uvicorn app.main:app &
uv run python scripts/check_interview_outcome.py   # py-9101: continue, py-9102: no_answer
```

## Запуск

```bash
uv run python -m app.interview --candidate-code py-9001 --no-core     # уточнения по текущей оценке
uv run python -m app.interview --candidate-code <code>                 # с ядром (строки interview профиля)
```

Нужна текущая оценка кандидата (см. сквозной прогон в [assessment.md](assessment.md)). Промпт — `guide-v1`.
