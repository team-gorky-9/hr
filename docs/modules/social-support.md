# Социальная помощь: реализация этапа 1

Самостоятельный пакет services/social-support, HTTP /api/v1/support.
Контракт: [wave-5-support-stage-1](../contracts/wave-5-support-stage-1.md).
Запуск и учебные роли: [README](../../services/social-support/README.md).

SQLite schema version 1: cases хранит текущий агрегат, history — неизменяемые
события по revision, rules — опубликованную учебную версию. Команды проверяют
ожидаемую редакцию внутри BEGIN IMMEDIATE и сохраняют событие в той же транзакции.
Документы имеют серверные UUID, SHA-256 и отдельные неизменяемые оригиналы.
Снимок подачи хранит текст и точный набор document_ids. Загрузка не означает подачу.

Проверки доступа учитывают организацию, заявителя, конкретное назначение и вид файла.
Координатор получает минимальную очередь; роль HR сама по себе не открывает материалы.
Файлы не доступны как статическая директория. Ответ скачивания — attachment,
application/octet-stream, nosniff, no-store. Внешний протокол остаётся internal.
Авторизация fixture предназначена исключительно для локальных учебных данных.

Реализованная часть 5A проверена настоящим HTTP, SQLite и рестартом процесса.
OpenAPI и ответы: docs/reports/wave-5a-support-*.json. Внешние системы и UI не проверены.

5B хранит staff_confirmation отдельно от роли employee. ChecklistResult содержит
submission_revision и точные document_id. Addenda создаёт новый снимок, заменяя
только выбранные пункты, и возвращает submitted; проверку нужно повторить.
История выдаёт заявителю public, назначенным сотрудникам также internal.

5C хранит все версии решений с автором внешнего источника и отдельным recorded_by.
Выписка строится по разрешённым полям, не из маскирования внутреннего протокола.
Правило отвода применено и к записи, и к чтению служебных материалов своего дела.

5D: отдельное assigned_executor_id с основанием; execution относится к ID решения,
хранит автора источника и регистратора раздельно. GET исполнителя ограничен очередью,
выпиской и исполнением; файл недоступен. Заявитель получает только публичную проекцию.
Закрытие хранит основание и действительный статус исполнения. Исправление решения
оставляет старый факт в истории и требует нового свидетельства для нового решения.

Итоговая проверка: четыре HTTP-теста, 4 passed. Финальные схемы и примеры:
[OpenAPI](../reports/wave-5d-support-openapi.json),
[ответы](../reports/wave-5d-support-examples.json),
[протокол](../reports/wave-5-support.md).
