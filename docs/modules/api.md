# Модуль HTTP API (`app/api/`, `app/main.py`)

Отдаёт фронтенду вакансии, отклики, оценки и очищенные тексты. На Этапе 1 только чтение: маршруты в базу ничего не пишут.

Контракт: [api.md](../contracts/api.md) v0.2. Опирается на [database.md](../contracts/database.md) v1.5: контуры п. 2.6.1, цитаты п. 2.11. Владелец — Денис. Потребители — фронтенд (Ася) и сквозная сборка `qa-01`.

## Запуск

Сначала база, миграции и справочники, как в [README](../../README.md#запуск-базы). Затем:

```bash
uv run uvicorn app.main:app --reload
```

- Swagger UI: http://127.0.0.1:8000/docs
- схема OpenAPI: http://127.0.0.1:8000/openapi.json
- проверка: `curl http://127.0.0.1:8000/api/v1/health` → `{"status": "ok", "db": "ok"}`

Переменные `.env` (образец — `.env.example`):

| Переменная | Зачем | По умолчанию |
|---|---|---|
| `DATABASE_URL` | база приложения | `postgresql+psycopg://hr:hr@localhost:5432/hr` |
| `CORS_ORIGINS` | адреса фронтенда, которым браузер разрешит запросы; JSON-список | `["http://localhost:5173", "http://127.0.0.1:5173"]` (Vite) |

## Маршруты Этапа 1

| Маршрут | Что отдаёт |
|---|---|
| `GET /api/v1/health` | `200 {"status":"ok","db":"ok"}`; база недоступна → `503 {"status":"error","db":"error"}` |
| `GET /api/v1/vacancies?contour=` | вакансии, утверждённый профиль в контуре, число откликов контура |
| `GET /api/v1/vacancies/{id}/applications?contour=&stage_code=&formal_result=&formal_preliminary=&assessment_status=` | отклики вакансии со статусом оценки |
| `GET /api/v1/applications/{id}` | карточка отклика: этап, обезличенная карточка кандидата, оценка с цитатами |
| `GET /api/v1/candidate-texts/{id}` | версия очищенного текста для панели источника |

`contour`: `working` (по умолчанию) — реальные кандидаты и рабочий профиль; `training` — учебные кандидаты (`py-9001`) и учебный профиль.

## Как устроено

```
app/main.py          create_app(): CORS, обработчики ошибок, роутер
app/api/routes.py    маршруты: разбор параметров → вызов services
app/api/services.py  чтение из базы, статус оценки, границы цитат UTF-16
app/api/schemas.py   DTO ответов (они же схема OpenAPI)
app/api/errors.py    ApiError и единый формат {"error": {code, message, details}}
```

- **Синхронные обработчики** (`def`): сессия SQLAlchemy синхронная (ADR-002 Р8), FastAPI выполняет такие обработчики в пуле потоков. Сессию на запрос выдаёт `Depends(get_session)` из `app/db/session.py` и закрывает её после ответа.
- **Слепой режим.** `services.py` не читает `CandidatePii` и `SourceDocument.raw_text`, в DTO таких полей нет. Карточка кандидата (`candidate.card`) — документ `CandidateCard`. Он уже без ПДн: модель извлекает его из очищенного текста.
- **Действующий профиль** выбирается только через `repository.get_approved_profile(position_id, synthetic=...)`. В `GET /vacancies` все должности обрабатываются одним запросом по тому же условию.
- **Контур карточки отклика** задаёт кандидат. У учебного берётся учебный профиль, у реального — рабочий. Так карточка всегда совпадает со строкой списка своего контура.

### Статус оценки (`assessment_status`)

Считает одна функция `services.resolve_states()`, общая для списка и карточки:

1. В контуре нет утверждённого профиля → `no_approved_profile`. В списке `formal_result = null`, у карточки `assessment = null`.
2. Есть текущая оценка по утверждённому профилю:
   - карточка этой оценки извлечена из текущей версии очищенного текста → `ready`;
   - иначе → `stale`, `stale_reason = "text_changed"`.
3. Есть только текущая оценка по **другому** профилю этой должности в том же контуре (утверждённый профиль с тех пор сменился) → `stale`, `stale_reason = "profile_changed"`.
4. Иначе → `not_assessed`: `formal_result = null`. Это не то же самое, что `formal_result = "unknown"`.

При `stale` значения прежней оценки отдаются (`formal_result`, `overall_score`), а интерфейс показывает предупреждение. Фильтры списка сравнивают отдаваемые значения.

Запросов на список фиксированное число (отклики, текущие тексты, оценки с карточками, текущие карточки), без N+1. Пагинации нет: на вакансию до ~430 откликов.

### Цитаты для браузера

В базе `start`/`end` — кодовые точки (срез Python `text[start:end]`). JavaScript считает строки в UTF-16, и символ вне BMP (эмодзи) там занимает две позиции. Поэтому каждая цитата (`EvidenceOut`) несёт ещё `utf16_start`/`utf16_end` = `len(text[:i].encode("utf-16-le")) // 2`. Считаются они по тому тексту, на который ссылается цитата. У устаревшей оценки это прежняя версия текста, и фронтенд берёт её через `GET /candidate-texts/{candidate_text_id}` из цитаты.

Пример `py-9001` (C5): текст `🙂 Написал API-тесты для сервиса заявок.`. Цитата `start=2, end=39`, в UTF-16 `utf16_start=3, utf16_end=40`.

### Ошибки

| Код HTTP | `error.code` | Когда |
|---|---|---|
| 404 | `VACANCY_NOT_FOUND`, `APPLICATION_NOT_FOUND`, `CANDIDATE_TEXT_NOT_FOUND` | нет сущности с таким UUID |
| 404 | `NOT_FOUND` | нет такого маршрута |
| 422 | `VALIDATION_ERROR` | неверный UUID или значение query; `details.errors` — где и что (без повтора ввода) |
| 422 | `UNKNOWN_STAGE_CODE` | `stage_code` нет в справочнике этапов |
| 500 | `INTERNAL_ERROR` | непредвиденная ошибка; текст исключения клиенту не отдаётся, он в журнале сервера |

## Что добавлено к примерам контракта

Эти поля описаны здесь, в `api.md` их нужно внести при следующей правке контракта:
- `stale_reason`: `text_changed` | `profile_changed`;
- `formal_checks[].key` — устойчивый ключ требования (`py.education.level`), по нему фронтенд сверяет строки с таблицей профиля;
- `candidate.is_training` и `candidate-texts.is_training`;
- `vacancy = null` в карточке отклика без вакансии на платформе (строки «Истории общения», `ingest-02`).

## Проверка

```bash
uv run pytest tests/test_api.py
```

Тесты строят сценарии настоящими функциями `repository` по контрольному набору `fixtures/assessment/py-9001.json`. Проверяется:
- статусы `unknown`, `met`, `not_met` (C1–C4), `not_assessed`, `no_approved_profile`, `stale` по тексту и по профилю;
- контуры: учебный кандидат скрыт из рабочего списка, счётчики откликов по контурам;
- альтернативы, `is_preliminary`, подтверждение документом (`basis`, `confirmed_by`);
- фильтры, пустой список, ошибки 404 и 422 в едином формате;
- границы UTF-16 на эмодзи;
- отсутствие ПДн и `raw_text` во всех ответах.

На базе из `.env` (например, с импортированным архивом):

```bash
uv run python scripts/check_api_blind_mode.py
```

Скрипт обходит все маршруты в обоих контурах и ищет в каждом ответе ПДн этого же кандидата из `candidate_pii`: ФИО, телефон, email, ссылки, дату рождения. Печатает статусы по вакансиям, время ответов и коды кандидатов с находками, без самих значений.
