# Модуль импорта откликов (`app/ingest/`)

Берёт пакет резюме и записывает его в базу:
- исходный документ;
- кандидата;
- персональные данные (ПДн) отдельно в `candidate_pii`;
- очищенный текст версии 1;
- отклик на этапе `new`.

В конце печатает отчёт без текстов резюме и без ПДн.

Контракты: [import.md](../contracts/import.md) (v0.1) и [database.md](../contracts/database.md) (п. 2.1–2.3, 2.8, 2.14, 11.7, 11.8). Владелец — Денис.

## Запуск

Сначала база и справочники, как в [README](../../README.md#запуск-базы).

**Синтетический контрольный пакет** (`fixtures/stage_0a/`, все данные вымышлены):

```bash
uv run python -m app.ingest --input fixtures/stage_0a --mapping fixtures/stage_0a/mapping.json
```

Ожидаемый итог на чистой базе (последняя строка в stderr):

```
импорт ingest-<дата-время>: total=4, imported=2, excluded_non_resume=1, quarantined=1
```

| Файл | Статус | Почему |
|---|---|---|
| `Python-разработчик/py-9001.txt` | `imported` | резюме на `python-dev`, контакты и имя вырезаны, контрольная фраза сохранена |
| `консультанта сектора подбора кадров/hr-9001.docx` | `imported` | резюме на `hr-consultant`, шапка hh.ru «Женщина, 31 год, родилась …» ушла в ПДн |
| `Python-разработчик/Вакансия.txt` | `excluded_non_resume` | служебный документ: сохранён как `vacancy_posting`, без кандидата |
| `Python-разработчик/py-9002.pdf` | `quarantined` | `PDF_NEEDS_REVIEW`: скан без текстового слоя |

Повторный запуск даёт `duplicate_skipped=2, excluded_non_resume=1, quarantined=1`. Число записей в базе не меняется.

**Реальный архив «Кадры»** (только локально: в архиве настоящие ПДн):

```bash
cd ../tools/hr_archive_parser && py parse_hr.py "<путь к Кадры.zip>" --output data/kadry
cd ../../hr
uv run python -m app.ingest --input ../tools/hr_archive_parser/data/kadry --mapping fixtures/kadry_mapping.json --report <файл отчёта вне Git>
```

Флаги:
- `--dry-run` — пробный прогон, всё откатывается в конце;
- `--batch <метка>` — метка запуска в `source_documents.import_batch`;
- `--report <файл>` — сохранить отчёт ещё и в файл.

Коды выхода:
- `0` — сбоев нет (карантин и конфликт считаются штатными статусами);
- `1` — есть статус `error`;
- `2` — неверные аргументы.

## Как проверить базу

```sql
SELECT count(*) FROM source_documents;               -- 3 после синтетического пакета
SELECT kind, count(*) FROM source_documents GROUP BY kind;
SELECT c.code, t.version, t.is_current, t.redaction_method
  FROM candidates c JOIN candidate_texts t ON t.candidate_id = c.id;
SELECT c.code, a.current_stage_code, p.code AS position
  FROM applications a JOIN candidates c ON c.id = a.candidate_id
  JOIN vacancies v ON v.id = a.vacancy_id JOIN positions p ON p.id = v.position_id;
```

Счётчики отчёта сходятся с таблицами так:
- `imported` = новые строки в `candidates`, `candidate_texts` и `candidate_pii`;
- `imported` + `application_added` = новые строки в `applications` и `stage_events`;
- `imported` + `excluded_non_resume` = новые строки в `source_documents` (повторно встреченный служебный документ новой строки не даёт).

Тесты `tests/test_ingest.py` проверяют это на настоящей PostgreSQL.

## Вход

Два режима, выбор автоматический:
1. **Выгрузка штабного парсера** — в папке есть `corpus.jsonl`. Текст берётся из `text`, байты — из `originals/<файл>`. Файлы, которые парсер не разобрал (`summary.json` → `errors`), попадают в отчёт как `quarantined` с причиной парсера.
2. **Папка с файлами** `.txt`/`.docx`/`.pdf`. Текст извлекается по тем же правилам, что и в парсере (`extract.py`):
   - TXT: UTF-8, UTF-16/32 с BOM, иначе CP1251;
   - DOCX: XML без дублирования объединённых ячеек;
   - PDF: только текстовый слой.

`source_path` в базе и отчёте — путь файла внутри пакета, в NFC и с `/`. В выгрузке парсера путь начинается с `Кадры/`.

## Сопоставление: `mapping.json`

```json
{
  "folders": {
    "Python-разработчик": "python-dev",
    "консультанта сектора подбора кадров": "hr-consultant"
  },
  "entries": [
    {"source_path": "Кадры/Кейс.pdf", "document_kind": "other", "channel": "internal"},
    {"source_path": "Python-разработчик/py-9001.txt", "candidate_code": "py-9001", "position_code": "python-dev"}
  ]
}
```

Как определяется должность, по порядку:
1. **`entries`** — запись для конкретного файла. Поля `document_kind`, `position_code`, `candidate_code`, `channel`, `file_format`; незаданные берутся из правил ниже.
2. **`folders`** — словарь «папка → код должности». Сравнение без учёта регистра и лишних пробелов. **Если папку переименовали, достаточно поправить ключ в словаре: код и тесты менять не нужно.**
3. **Значения по умолчанию** — `POSITION_CODE_BY_FOLDER` из `app/db/seed.py` (папки архива «Кадры»).
4. Папки нет нигде — `quarantined` с причиной `UNKNOWN_POSITION`. Должность по тексту резюме не угадываем.

Тип документа по имени файла (`package.py`):

| Имя файла | Тип |
|---|---|
| `отклик N`, `Резюме N`, `py-9001` | `resume` |
| `Вакансия.*` | `vacancy_posting` |
| слово `ДИ` | `job_description` |
| `матриц…` | `competency_matrix` |
| папка `Положения` | `regulation` |
| прочее | `quarantined` (`UNKNOWN_DOCUMENT_KIND`), тип задаётся в `entries` |

Для архива «Кадры» такие записи лежат в `fixtures/kadry_mapping.json`: две ДИ без «ДИ» в имени, ДИ QA и `Кейс.pdf`.

Код кандидата — `<префикс должности>-<номер файла из 4 цифр>` (контракт БД, п. 11.2):
- префиксы: `jpy`, `py`, `qa`, `fe`, `ux`, `hr`;
- пример: `отклик 5.txt` в папке Python → `py-0005`;
- для должности без префикса код задаётся в `entries`.

## Статусы и дубли

| Ситуация | Статус |
|---|---|
| новый файл, вакансия найдена, очистка прошла | `imported` |
| те же байты (даже под другим именем), та же вакансия | `duplicate_skipped` |
| те же байты, другая вакансия | `application_added`: второй отклик того же кандидата |
| другие байты, но код кандидата занят | `conflict`, ничего не пишется |
| разные файлы с одинаковым извлечённым текстом | оба `imported`, у второго предупреждение `duplicate_text_warning` |
| служебный документ | `excluded_non_resume`: документ сохраняется без кандидата |
| проблема в данных: нет текста, скан, неизвестная папка или вакансия, остатки ПДн после очистки | `quarantined` |
| сбой программы или базы | `error`: в причине только тип ошибки, без текста |

**Транзакции.** Каждый файл обрабатывается в своей точке сохранения (`SAVEPOINT`): ошибка откатывает только этот файл, частичного кандидата не остаётся. После каждого файла делается `commit`, кроме режима `--dry-run`.

## Очистка ПДн (`redact.py`)

Работает без нейросетей. NER Natasha пробовали: верных находок было ≈20 %. Замер описан в штабе, `hq/work/2026-11-19-stage-0a-01-import/plan.md`.

1. **Шаблоны контактов.** Email, телефоны (в том числе с неразрывными дефисами и пробелами), ссылки на профили (github, t.me, vk, linkedin, hh.ru/resume, behance, `*.github.io` …), ники `@ник`. Аннотации `@Override` и декораторы `@pytest.mark…` ником не считаются.
2. **Шапка hh.ru.** «ФИО N», «Кандидат №N», `mailto:`. Строка «Женщина, 48 лет, родилась 7 июля 1978» уходит в `gender`, `age`, `birth_date` и заменяется меткой.
3. **Подписанные поля.** «Телефон:», «Почта –», «Тг:», «ФИО:», «Дата рождения –», «Тел. + (…)»: значение скрывается.
4. **Имена по подсказкам.** Подсказки бывают двух видов:
   - сильные («С уважением,», «Меня зовут») — берём слово сразу;
   - слабые («Спасибо», «Я —», строка рядом с контактами) — только если словарь `pymorphy3` знает слово как имя, фамилию или отчество.

   Отдельно ловятся ФИО с отчеством и рекрутеры в блоке работодателя hh.ru («Автор: …»). Рекрутеры маскируются, но в `PiiData` не попадают.
5. **Распространение.** Найденные имена во всех падежах и ники скрываются по всему тексту.
6. **Проверка.** Если в тексте осталось что-то из найденного, телефон, цепочка из 10–12 цифр, email или дата рождения, а также если после очистки почти нет текста, — запись уходит в `quarantined`, и модель её не видит.

Метки в тексте: `[имя скрыто]`, `[контакт скрыт]`, `[ссылка скрыта]`, `[пол, возраст и дата рождения скрыты]`, `[номер кандидата скрыт]`.

Не трогаем:
- род глаголов (п. 11.7);
- город и гражданство (п. 11.8, проект v1.1);
- блок работодателя hh.ru «Комментарии/История» — остаётся по решению Дениса, в отчёте у таких записей предупреждение `employer_block_present`.

Версия правил пишется в `candidate_texts.redaction_method` (`ingest-rules v1`). Улучшенную очистку загружают новой версией текста через `add_candidate_text`.
